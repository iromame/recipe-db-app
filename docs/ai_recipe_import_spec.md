# レシピAI自動抽出＆画像保存機能 仕様書

## 1. 概要
ユーザーがアップロードした料理本や手書きメモの写真、またはWebサイトのテキストから、Gemini APIを利用してレシピの構造化データ（JSON）を抽出し、アプリの登録フォームに自動入力する機能。
同時に、**アップロードされた画像はレシピの「完成画像（または参考画像）」としてCloudflare R2等に保存**し、破棄せずに活用する。

## 2. システムフロー

1. **アップロード**: フロントエンドから画像ファイル（またはテキスト）を送信。
2. **AI抽出＆画像保存 (並行処理)**:
   - **画像保存**: 送信された画像をCloudflare R2バケットに保存し、公開URLを生成。
   - **AI抽出**: 画像（またはテキスト）をGemini API (例: `gemini-1.5-flash`) に送信し、レシピデータをJSON形式で抽出。
3. **データ返却**: 抽出されたJSONデータと、保存した画像のURLをフロントエンドに返す。
4. **フォーム反映**: 返却されたデータを `RecipeForm` の初期値としてセット。
5. **最終確認＆保存**: ユーザーが内容を目視確認・修正し、「保存」ボタンを押下してD1データベースに最終保存する。

---

## 3. バックエンド仕様 (Cloudflare Workers / Hono)

### 3.1 必要な環境設定
*   **Gemini API Key**: `GEMINI_API_KEY` をCloudflare Workersのシークレットに登録。
*   **Cloudflare R2**: 画像保存用のバケットを作成し、Workerにバインディング（例: `R2_BUCKET`）。画像の公開プレビュー用にカスタムドメインまたはR2.devドメインを有効化。

### 3.2 エンドポイント
`POST /api/recipes/extract`

#### リクエスト
*   **Content-Type**: `multipart/form-data`
*   **Body**:
    *   `file` (File形式): アップロードされた画像ファイル
    *   `text` (String形式): （テキストから抽出する場合）クリップボード等のテキストデータ

#### 処理の流れ
1. リクエストからファイルまたはテキストを受け取る。
2. **画像がアップロードされた場合**:
   - 一意なファイル名（UUID等）を生成し、R2バケットに `put` する。
   - `imageUrl` を生成する。
3. **Gemini API呼び出し**:
   - テキスト、または画像データをBase64エンコードしてGemini APIへ送信。
   - 指示文（システムプロンプト）にて、 Schema.org / Drizzleスキーマ に準拠した構造を強制し、`application/json` でレスポンスを受け取るように指定（Structured Outputs 機能を利用）。
4. **レスポンス返却**:
   抽出されたデータパースし、これに `imageUrl` を結合してフロントに返す。

#### プロンプト指示内容（例）
*   `title`
*   `description`
*   `prepTime` / `cookTime` (ISO 8601形式縛り)
*   `mode` (MAKE_AHEAD, LUNCH, DINNER)
*   `tags` (文字列配列)
*   `ingredients` (名前と分量)
*   `instructions` (手順の配列)

#### レスポンスモデル
```json
{
  "success": true,
  "data": {
    "title": "...",
    "description": "...",
    "prepTime": "PT10M",
    "cookTime": "PT20M",
    "mode": "LUNCH",
    "tags": ["..."],
    "ingredients": [{ "name": "...", "amount": "..." }],
    "instructions": ["..."],
    "imageUrl": "https://r2.example.com/uuid.jpg" // R2に保存された画像URL
  }
}
```

## 4. フロントエンド仕様 (React / Vite)

### 4.1 UI要件 (モバイルファースト・片手操作前提)
*   **アクションボタン**:
    *   「カメラで読み取る / 写真を選ぶ」ボタン
    *   「テキストから読み取る」ボタン
*   **ロード状態**:
    *   AIの解析処理には数秒かかるため、分かりやすいローディング表示（スケルトンやプログレスアニメーション）を実装する。

### 4.2 フォームの自動バインディング
*   抽出APIからデータが返ってきたら、既存の `RecipeForm` (例: `react-hook-form`) に対して `form.reset(data)` 等で一括流し込みを行う。
*   返ってきた `imageUrl` もフォームステート（またはプレビュー表示）にセットしておく。

### 4.3 Human-in-the-loop (ユーザー直接介在処理)
*   AIはOCRの誤認識や時間の解釈ミスを行う可能性があるため、直接バックエンドへは保存（INSERT）しない。
*   必ず編集フォームを介し、ユーザーの目で内容を最終確認・修正させるフローとする。
*   最終的に「保存」ボタンが押されたタイミングで、既存の作成API (`POST /api/recipes`) を叩き、D1にデータベース登録する。

---

## 5. 残課題 / 検討事項
*   **古い画像のクリーンアップ**: AI抽出はしたものの「やっぱり登録をやめた」場合、R2バケットには画像だけが残り続ける。これを防ぐため、定期的なバッチ（Cron Worker等）でD1に紐づかないR2オブジェクトを削除する仕組みの導入を検討。
*   **セキュリティ**: R2に保存される画像のサイズ制限（Cloudflare Workersのリクエストサイズ上限に注意）や、ファイル拡張子のバリデーションを設ける。
